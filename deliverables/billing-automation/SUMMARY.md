# billing-automation — summary (written by the orchestrator; the harness does not let sub-agents write report files)

The billing layer in `automation/billing/` is offline-tested Node (28/28): `pricing.seed.json` is the only place a tier price is typed (3.6); `reference.js` settles the payment reference as `LV-{billing_ref}-{tier}-{YYYYMM}` (NH-26 draft; parser also accepts the 6.5 form; ±R1 amount tolerance); `paystack.js` (signature check via `automation/security/verify-webhooks.js`, per-tier pages + optional auto-renew plans, Instant EFT/card init, verify, refund, card charge, four webhook events → one "payment received" event, live-key refusal); `incontact.js` (FNB alert parser with sender/subject/DMARC filters and a format-change detector, checked against 20 synthetic alerts); `reconcile.js` (auto-pay only on reference + amount match; partial/overpaid/no-reference/wrong-tier/wrong-period/already-paid → console queue; duplicates and Paystack payouts never double-counted; CSV/OFX import; daily report); `price-diff.mjs` (repo scan: FAILS as expected with 47 typed prices in 13 files, all 7 legacy locations included). W16 (47 nodes), W17, W18, W19, W25 are generated from the same modules by `build-workflows.mjs`. `billing/checkout/` is the static three-option checkout (Instant EFT default, manual EFT with bold reference + copy, card auto-renew optional and unticked). `RUNBOOK.md` and `PRICING-CONSUMERS.md` document the gates and the 10 price consumers. Manual EFT + inContact parsing is a complete payment path while Paystack KYC is pending (0.3 #5). Thirteen needs_human lines are logged in `build/needs-human-log.md`; the money ones (VAT basis of media_share_zar, card auto-renew on our 30-day cycle not Paystack monthly plans, no mid-cycle pro-rata, broker row created at invoice issue) are in the gate list as NH-27.

# intro-media-producer — summary (written by the orchestrator; the harness does not let sub-agents write report files)

The Step 5 "Record your intro" prototype (`portal/intro-media/`) is built from the approved design on the brand tokens: 8-question interview (the ten 4.10 prompts folded into the eight the approved design shows), three scripts with a live FAIS gate, a recorder with teleprompter, 3-2-1 countdown and instant plain-English checks, up to three takes, audio-only, file-upload fallback, WhatsApp-capture slot, and an approve screen showing the real `intro_media` / `intro_media_voice` wording; it ran end to end in headless Chromium with a fake camera (real iOS/Android devices still to test). `automation/W23.json` (52 nodes) takes a portal upload or a WhatsApp video from a known broker number, raw-checks, transcribes (Whisper-class endpoint by env), runs the spoken-word FAIS gate, then `automation/media/pipeline.sh` (ffmpeg: trim silence, 9:16 H.264 ≤ 16 MB, burned-in captions, lower-third, end-frame, thumbnail, OGG/Opus) — run for real on a synthetic clip; a Haiku thumbnail check; versioned storage and `broker_media` rows; approval makes a take current. `media.test.js` passes 10/10. `deliverables/intro-media/` holds the checklist with reasons, rubric, script prompt (day-neutral close, see needs_human), explainer storyboard and the measurement plan (video vs voice vs none over the first 100 bookings). Ten needs_human lines are logged in `build/needs-human-log.md`.

## API auth switch (I-32a) — 2026-10-02
The intro recorder no longer depends on a same-origin `/intro/*` proxy or a cookie. At build, `portal/intro-media/inject-api.mjs` bakes `VITE_N8N_WEBHOOK_BASE` into each page's `data-api` attribute (and the Supabase storage key into `data-sb-key`). The recorder then calls `{API_BASE}/intro/...` with `Authorization: Bearer <Supabase access token>`, read from the portal's own session on the same origin (`credentials: 'omit'`, no broker id ever sent). W23's browser-facing endpoints, `intro/upload-confirm` and `intro/approve`, now begin with a JWT check using the same `verifySupabaseJwt` as the broker `/slots` path (HS256 on `SUPABASE_JWT_SECRET`, fails closed on a missing secret, broker from `brokers.user_id = sub`, `approved_by` = token `sub`); CORS pinned to the portal origin; 401/403/200 via Respond nodes. Media-row, pipeline, versioning and spot-check logic unchanged; `automation/media/patch-w23-auth.mjs` re-applies the patch after any `lead-token.js` change (sha stamp tested). Tests: media 10 + w23-auth 9 = 19 pass. Docs: `portal/intro-media/README.md`, `deliverables/intro-media/api-auth.md`. No React edit needed.
**Open:** `status`, `interview`, `script-select` and the signed-URL half of `upload` have no n8n workflow yet (recorder works only with `?mock=1`) — automation-engineer with conversation-designer's script gate; HS256 vs JWKS assumption; CORS allowlist needs the staging/tunnel origins; static-hosting.md §6 to mark decided and add `data-api`/`data-sb-key` to build steps; the upload-confirm body is trusted beyond the broker-row lookup (take ownership check).

## Remaining /intro endpoints (I-37a, 2026-10-02)
`automation/W23.json` (97 nodes) now has `GET intro/status`, `POST intro/interview`, `POST intro/script-select` and `POST intro/upload`, each behind its own "Verify broker JWT" node with the broker from `brokers.user_id = sub`: status is read-only (step, gate-passed script candidates only, takes, approval state, chosen script); interview stores typed answers (question id `[a-z_]{2,16}`, ≤ 2,000 chars) into `brokers.positioning_answers`, no LLM; script-select picks one of `positioning_answers.script_candidates` with `gate_pass` true — edited/free text returns `pass:false`, never stored; upload builds `<broker uuid>/<language>/<take_id>.<ext>` and requests a signed upload URL for the private `broker-media` bucket (credential name `Supabase Storage (service role)` only); upload-confirm returns 403 unless the object key starts with the caller's uuid and has no `..`. `patch-w23-auth.mjs` generates all of it (idempotent). Recorder: mock is now opt-in per tab session; README documents endpoints and env. Tests 25/25.

# platform-architect: Phase 0 summary (P0-INVENTORY)

`build/inventory.md` is the 0.2 reuse-first inventory of the existing Lead Velocity CRM. That CRM is a React/Vite SPA on Vercel backed by Supabase project `cmsylaupctrbsvzrgzwy`. The inventory covers 26 tables defined in repo SQL plus 12 tables referenced but defined nowhere (live-schema drift); the admin/broker roles and RLS; the full route map; all 35 edge functions; the existing generators, with hard-coded proposal, invoice and contract prices; the wired integrations (Twilio, ElevenLabs, Gemini, Resend, Discord/Telegram, but no Meta, Graph or Paystack); the Einstein/Ayanda personas; and the security findings. It notes that there is no test setup. It also lists the assets that are not in the repo, which Jonathan must supply (Q4b). `build/crm-gap.md` maps every target table, screen and workflow (W01–W35) to reuse as-is, extend or new. The three biggest gaps:
1. Nothing for money and cycles exists: `pricing`, `cycles`, structured `invoices`, `bank_credits` and Paystack are all new, and prices are hard-coded in seven places.
2. The lead's path after intake does not exist: consent and attribution fields on `leads`, a Graph-backed booking, `outcomes`, `replacements`, and WhatsApp Cloud API messaging.
3. There is no audit log and the live database has POPIA-grade RLS holes, which must be closed before any consumer data lands.

The gap map recommends NH-09: keep Supabase Postgres as the single system of record, with n8n on the VPS as a client and the VPS Postgres holding n8n state only. It also raises NH-11 (live schema dump), NH-12 (Vercel vs Hostinger hosting), NH-13 (Resend vs Graph email), NH-14 (legacy B2B tiers vs the SortMyCover ladder), NH-15 (security fixes and rotating the passwords in tracked scripts), NH-16 (an `ops` schema to avoid the `proposals`/`notifications` name clashes) and NH-17 (processors missing from the POPIA list).

## Console + broker portal (React, flagged) — 2026-10-02
platform-architect built the SortMyCover operator console and broker portal inside the existing React/Vite CRM (0.2 reuse: same Supabase client, has_role, BrokerLayout). Everything sits behind `VITE_SMC_ENABLED`, default off; with it off the legacy app is unchanged (verified: `vite build` passes with the flag off and on; 0 TypeScript errors in the new files, legacy error count unchanged). No new npm dependencies, no SQL, no legacy page edited beyond one optional `menuItems` prop on BrokerLayout and lazy routes in App.tsx. Console (admin only): `/console` Today (pulse card Approve / Snooze 7 d / Decline → `ops.proposals` + `ops.notifications` outbox; 7 watchlist tiles with sparklines from `smc_watchlist_tiles()`; faculty strip; signals; judge findings; history), `/console/ads` (campaign → ad set → ad from `ad_metrics`/`ad_objects`; pause/resume/budget only via n8n preview-then-confirm, nothing calls Meta from the browser), `/console/ask` (n8n webhook, "not enough data yet" under n = 20).

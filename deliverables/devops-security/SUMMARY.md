# devops-security — summary (written by the orchestrator; the harness does not let sub-agents write report files)

`automation/security/` is a tested zero-dependency webhook-verification module (Meta/WhatsApp signatures + handshake, Paystack, Twilio, replay window, idempotency, log redaction; 11 tests) with a paste-in n8n pattern and `SECURITY.md` (token map, `.env` and redaction policy, OWASP ASVS L1 checklist, the NH-15 fix runbook in §5 without any secret value). `automation/W22.json` + `W22.md` is the single alert switchboard: thresholds from 3.4/6.3/6B/Section 7 each with its source, one-statement dedupe (same alert ≤ once per 24 h), quiet hours 22:00–07:00 SAST except the 6.8b always-send set, escalation (re-send to the other partner at 2 h, Twilio voice at 4 h), hourly encrypted Flow-endpoint ping that reverts `booking_ui` to the list on failure, uptime/WABA/DKIM-DMARC checks, everything written to `ops.notifications` (13 tests, SQL exercised on a throwaway Postgres). `automation/backup/` age-encrypts nightly `pg_dump` before it leaves the process, keeps 30 days plus a 5-year consent archive, with a monthly restore test on the laptop. `automation/vps/` is W26: one human gate (Jonathan buys the VPS) then `provision.sh` (13 idempotent steps, dry-run by default, halts on first failure, never unpauses anything; 5 tests) + Traefik compose + uptime. `automation/dns/DNS.md` covers both domain scenarios and DKIM/DMARC with `dns.google` checks; `automation/local/LOCAL-STAGING.md` the laptop n8n + tunnel. Combined, 135/135 tests pass across every agent's test files. Twelve needs_human lines are logged in `build/needs-human-log.md`; the DMARC start policy, backup target, n8n SSO alternative and the docker-compose env scope go to owners or the gate list (NH-29).

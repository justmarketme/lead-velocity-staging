# ads-api-engineer: SUMMARY

Built the Meta Marketing API layer, offline and untested against Meta (no token exists; nothing is called live). `automation/ads/meta-ads.js` is a no-dependency Node 18+ client: system-user token sent as a Bearer header, usage-header parsing with back-off at 80% (`RATE_LIMIT_BACKOFF` with `retryAfterMs` when the wait is long), 50-call batches, retries, hourly-only insights (`TOO_SOON`), and confirm-to-apply on every write (HMAC token bound to action, target and parameters; single use; 15 min). Writes return audit_log and ops.notifications rows (who/when/why) and never touch the database. Covers budget (daily and monthly caps, minimum, 20% step, 48 h cooldown), pause/resume, campaign tree from a spec (everything PAUSED at the minimum budget, naming `C{concept}_{angle}_{format}_{date}`, Special Ad Category must be stated, no interest targeting, no Get-quote CTA), lead form, Lead Ads webhook subscription, `fetchLead`, backstop qualification, asset health for W27, engagement/customer-list (hashed only)/lookalike audiences (seed >= 1,000), and offline events via `capi.js`. `meta-ads.test.js` (20 tests, offline) passes. `W21.json`, `W27.json`, `W02.json` are valid n8n JSON (credential by name, secrets from env). `CONSOLE-ADS-API.md` is the Ads screen contract and lists what stays in Ads Manager.

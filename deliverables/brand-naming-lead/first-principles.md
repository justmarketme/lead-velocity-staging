# First-principles memo: brand-naming-lead (one page)

**The number I move:** brand recall and branded search for "SortMyCover" (Search Lift), plus zero availability or legal collisions.

**What is true, and where it comes from (my five only):**
- People notice and recall **names and logos** much more than colours (~4% owned) or taglines (~6%). *Ehrenberg-Bass / Romaniuk.* So the wordmark and tick get the investment, and colour is support.
- Recognition builds only through **unchanged repetition**, and consistency lowers CPL over time even in a performance funnel. *Binet & Field.* So one kit, every surface, no local variations.
- **The name is the positioning.** "Sort my cover" says the outcome in the customer's words. In a category of shields and blue, that is the zag. *Neumeier.*
- **Colour-trust links are weak and depend on context.** Trust comes from things people can verify. *Labrecque & Milne / trustworthy-blue studies.* So amber was chosen for contrast and ownability, and trust lives in the disclosure, the named company and the named adviser.
- **Ads create branded search** (+4% average, up to +39%). *Meta Search Lift.* So the name must be typable and the exact domain, handles and profiles must be ours before the first impression. Brand and performance are one budget.

**What follows from that:**
1. Checks before kit. A name we can't own breaks all five, so the availability checklist ships first and its ★ rows are blocking. I could not run them (no web access), so no result has been guessed.
2. Colour values live only in `brand/tokens.json` (6B.8). The bible carries placeholders, so the pipeline cannot drift.
3. One disclosure, short forms derived from it, no new claims. contracts-drafter owns the words.
4. CoverKlaar should not become a second brand by default. Two names split recall and branded search. Recommendation: run Afrikaans under SortMyCover and keep CoverKlaar defensive (Jonathan decides).

**What I checked instead of assuming:** I computed the WCAG contrast of the 4D.4b.4 palette. Amber on charcoal is ~7.3:1, which passes AA for normal text, so the prompt's "large text only" note is wrong (the usage rule stays). Amber on off-white is ~1.9:1, so never use amber text on light backgrounds.

**Handoff to visual-producer (values for `tokens.json`, naive conversion, proof before print):** amber ≈ C0 M32 Y86 K4; charcoal ≈ C39 M20 Y0 K80; off-white ≈ C0 M1 Y4 K2.

**C-claim, measured not believed:** "friendly names convert better in finance" cannot be isolated with one name live. Week-1 WhatsApp reply rate is logged against the 4.6 model as a proxy only.

**What I won't do:** shields, umbrellas or blue; generic-descriptive names; colour psychology as a reason; any public use of a name with a ★ CONFLICT.

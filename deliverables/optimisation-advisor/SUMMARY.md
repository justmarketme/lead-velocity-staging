## W32 console outbox (I-34d) — 2026-10-02, by automation-engineer in the W32 generator
W32 now takes console Approve, Snooze and Decline decisions from `ops.notifications`. A 1-minute poll claims rows (kind `approval`, source `console`, status `queued`) with `FOR UPDATE SKIP LOCKED LIMIT 20` and runs each through the existing decision branch as a self-call, then sets `acked` or `send_failed` (guarded on `status='sending'`). The `smc-w32-decision` webhook stays for the WhatsApp Approve button only, so a webhook caller cannot impersonate the console. `Decide` gained a `via` parameter: on the console path it matches only a proposal already decided by the console with `task_id is null`, so the build task is created exactly once instead of matching nothing. All changes are in `optimisation/build-workflows.cjs`; W32.json regenerated and in sync, W33 byte-identical. Tests: W32 9 (new), optimisation 24 unchanged.

## Confirm to approvers (I-36a) — 2026-10-02
Confirm to approvers is now implemented in `optimisation/n8n-code/w32-approve-confirm.js`. After an approved proposal gets its build task, it emits one WhatsApp item per approver (`ops.alert_recipients`; kind `approval_confirmed`, 24 h dedupe per proposal and recipient) through Reserve notification and the shared send, with the task id and a Today button. It never throws: a missing task, no recipients or any error is logged and returns no items, so the console poll acks the row instead of marking it `send_failed`. The `Decide` `via='console'` edit was reviewed and kept, and is now tested to match only a console-decided proposal with `task_id` null (the console RPC in migration 08 sets `decided_by_label='console'`). W32 is 127 nodes and in sync; the three suites total 35 passing tests (W32 11, optimisation 24). The confirmation template `ops_action_confirmed` (body {{1}} title, {{2}} task id, {{3}} owner agent, {{4}} check date, {{5}} approved by; URL button `https://app.leadvelocity.co.za/{{1}}` example `today`) is being drafted by the templates owner; until it is approved the send fails and is logged on the notification row, and the console flow is unaffected.

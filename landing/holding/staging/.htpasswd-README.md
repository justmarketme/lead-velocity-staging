# Staging basic-auth setup (no passwords in this repo)

Staging host: `sortmycover.leadvelocity.co.za`. Never linked publicly, never shown to consumers or Meta.

1. In hPanel create the staging site (subdomain of leadvelocity.co.za) with its own document root. Do not reuse the production root.
2. Preferred: hPanel > Websites > Dashboard > Password protect directory (Hostinger writes `.htpasswd` outside `public_html`). Pick a long random password, store it in the password manager, never in git or chat.
3. Manual alternative: generate the file locally (`htpasswd -c .htpasswd <user>`), upload it above `public_html`, and add to the staging root `.htaccess`:

```
AuthType Basic
AuthName "SortMyCover staging"
AuthUserFile /home/<hostinger-user>/domains/<staging-domain>/.htpasswd
Require valid-user
```
4. Upload the same files as production. The shared `.htaccess` already sends `X-Robots-Tag: noindex, nofollow` for this host, and skips the redirects.
5. Verify: `curl -I https://sortmycover.leadvelocity.co.za/` returns 401 without credentials; with credentials it returns 200 and the `X-Robots-Tag` header.
6. `.htpasswd` is git-ignored and the secret guard blocks it. Do not commit it.
